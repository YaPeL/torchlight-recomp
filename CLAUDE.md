# Torchlight 360 — native render backend (rhi-rewrite branch)

## Context

Port of Torchlight (Xbox 360) statically recompiled with ReXGlue. The guest uses OGRE 1.7.0
"Cthugha", possibly with Runic's patches. Instead of emulating the Xenos GPU, we cut at the guest
OGRE's RenderSystem and rebuild every draw in a native OGRE 14 (GL) on the host. The guest OGRE keeps
running whole: SceneManager, materials and culling. Only the layer below (D3D9/Xenos) is replaced.

## Reference repositories (read only)

- `~/torchlight-agent-worktree` (tag `legacy-detached-ogre`): the previous attempt. Useful to look
  up offsets, guest addresses and the sync logic. Do NOT copy its architecture or its probes. Every
  fact taken from it is verified again.
- `~/ogre-1.7.0` (OGRECave/ogre, tag `v1-7-0`): reference headers of the guest OGRE. They are the base
  hypothesis for class layouts and vtable order; every offset and slot is confirmed with accesses in
  the recompiled code. Whatever does not match is marked as a "Runic difference", without forcing it.
- `~/ogre14-install`: the host's OGRE 14.6.0 (headers + libs; recipe in the README).
- `~/torchlight-recomp/reference/pc`: Torchlight PC binaries (OGRE 1.6.x). There is no Torchlight PC
  source code.

## Target architecture

```
guest RenderSystem vtable hooks  ->  command stream  ->  host backend (OGRE GL)
                                          |
                                     capture/replay (one file per frame)
```

1. `guest_abi/`: offsets and vtable slots of the guest's OGRE classes. The only place where layout
   magic numbers live. Every constant cites its evidence (PC header + line, recompiled function +
   address).
2. `hooks/`: intercept the guest RenderSystem's virtuals and the `create`/`lock`/`unlock` of buffers
   and textures, plus the present (`VdSwap`). They only translate arguments into commands; no render
   logic.
3. `commands/`: neutral command format (no OGRE or PPC types). Serializable.
4. `backend/`: host OGRE. Resources mirrored by guest identity (pointer + generation), state tracker,
   draw, frame/present.
5. `sync/`: fences and events the guest expects from the GPU (port the legacy's `detached_sync.cpp`,
   which works).
6. `replay/`: standalone executable that reads captures and sends them to the backend.
7. `diag/`: all diagnostics, behind ONE build flag.

## Hard rules

- FORBIDDEN to admit, fix or treat a draw differently by hash, signature, mesh name or material name.
  All behavior is generic, by capability or state.
- FORBIDDEN to add environment variables. If configuration is needed, ask first.
- FORBIDDEN to create "evidence", "audit", "package" or "objective" documents. The documentation is
  `docs/ARCHITECTURE.md` and comments in the code, nothing else.
- FORBIDDEN to add a probe or trace "to see what happens" without agreeing on it first. If something
  cannot be solved by reading the guest code or the reference headers, STOP and ask.
- Do not touch code generated by ReXGlue or the SDK.
- Guest (OGRE 1.7.0) and host (OGRE 14) are different versions: no enum (AutoConstantType,
  VertexElementType, OperationType, etc.) is assumed equal between them. All are mapped explicitly in
  `guest_abi/`.
- `backend/`: no direct GL calls. Everything goes through OGRE's API, so as not to be tied to one
  render system.
- `backend/`: the D3D/Xbox vs GL differences (inverted Z, projection conversion, vertex color format,
  half pixel, UV origin) are handled in a single place of the backend, with an explicit name. Never
  corrected by eye anywhere else.
- The boundary with the backend is a C API (`backend/backend_api.h`): no OGRE type leaves
  `backend/`.
- Guest memory is big-endian and 32-bit. Every read goes through the `guest_abi/` helpers; never cast
  guest pointers to host structs.
- Cross-platform (Linux, Windows, macOS, Steam Deck): all platform-specific code (X11, GLX, SDL's
  video driver, the child window, keys read from the window system) lives isolated in a platform
  module with a common interface. No platform `#ifdef`s or window system includes scattered across
  the rest of the code.

## Way of working

- Small tasks, with a verifiable done criterion. One commit per logical unit, with a clear message.
- Everything in the repository (code, comments, documentation, commit and tag messages) is in
  English.
- Before writing code for a new task: plan, wait for approval.
- Every change is validated with a unit test or a replay. If it cannot be validated either way, say
  so explicitly.
- Run the real game only when agreed (new captures or milestone validation).
- If a hypothesis fails twice, stop and report instead of iterating further.
- When closing a task, report in a few lines: what changed, how it was verified and what is still
  open.

## Data inherited from the legacy (VERIFY before using)

- `0x821CEA60`: common `RenderSystem::_render` (OGRE-common).
- `0x821C4058`: guard before `_render` (`*(op+0)` -> `+20` != 0).
- `sub_821B1000`: wrapper of the guest's `_endFrame`.
- `__imp__VdSwap`: the guest's present request; the host frame closes there.
- `HardwareVertexBuffer+96`: backing storage (according to the legacy).
- Sync: only the calls to `sub_821F3D78` with `r7 == 1` need retiring; see the legacy's
  `detached_sync.cpp`.
